# Лабораторная работа №3
## Разработка веб-приложения с использованием Express.js, EJS и middleware
### Приложение

Приложение позволяет:
- просматривать список учебных курсов;
- просматривать подробную информацию о курсе;
- добавлять новые курсы;
- редактировать и удалять курсы;
- искать курсы по названию или преподавателю;
- фильтровать курсы по семестру;
- одновременно использовать поиск и фильтрацию.

Данные в данной работе хранятся в массиве в памяти, поэтому после перезапуска сервера изменения сбрасываются.

### Использованные технологии

- **Node.js**
- **Express.js**
- **EJS**
- **HTML/CSS**
- **JavaScript**
- Архитектура **MVC**

### Реализация

В `models/courseModel.js` был создан массив учебных курсов с полями `id`, `title`, `teacher`, `credits`, `semester` и `description`.

В `routes/courseRoutes.js` были определены маршруты для выполнения CRUD-операций:

- `GET /courses` — список курсов;
- `GET /courses/:id` — информация о курсе;
- `GET /courses/new` — форма добавления;
- `POST /courses` — добавление курса;
- `GET /courses/:id/edit` — форма редактирования;
- `POST /courses/:id/edit` — сохранение изменений;
- `POST /courses/:id/delete` — удаление курса.

Основная логика обработки запросов была вынесена в `courseController.js`, поэтому маршруты не размещались непосредственно в `app.js`.

### Поиск и фильтрация

На странице списка курсов реализован поиск по названию дисциплины и имени преподавателя без учёта регистра.

Также реализована фильтрация по семестру. Поиск и фильтрацию можно применять одновременно, например:

```text
/courses?search=node&semester=1
```

В этом случае отображаются только курсы, соответствующие обоим условиям.

### Валидация

Для проверки данных формы был создан middleware `validateCourse.js`.

При добавлении и редактировании проверяется:
- заполнено ли название;
- указан ли преподаватель;
- является ли количество кредитов положительным числом;
- является ли семестр целым числом от 1 до 8;
- заполнено ли описание.

При ошибке пользователь получает понятное сообщение, а введённые данные сохраняются в форме.

### Логирование

В `middleware/logger.js` реализовано логирование всех HTTP-запросов.

В терминале выводится:

```text
HTTP Method | URL | Date and Time
```

Например:

```text
GET | /courses | 07.10.2026 13:25
POST | /courses | 07.10.2026 13:27
```

Middleware подключён до маршрутов, поэтому применяется ко всем запросам приложения.

### EJS и оформление

Для создания динамических страниц использовался шаблонизатор **EJS**.

Повторяющиеся элементы интерфейса были вынесены в `header.ejs` и `footer.ejs`. В header размещены название приложения и навигация, а в footer — информация о студенте, группе и текущем годе.

Для оформления приложения создан файл `public/css/style.css`, в котором стилизованы навигация, таблица курсов, формы, кнопки, сообщения об ошибках и страницы просмотра курса.

### Обработка ошибок

Для обработки ошибок были созданы страницы:

- `404.ejs` — для несуществующих маршрутов и курсов;
- `error.ejs` — для внутренних ошибок приложения.

На странице 404 отображаются код ошибки, сообщение, запрошенный URL и ссылка на список курсов. Техническая информация и stack trace пользователю не показываются.

### Запуск приложения

Для создания проекта и установки зависимостей были использованы команды:

```bash
npm init -y
npm install express ejs
```

Для запуска приложения:

```bash
node app.js
```

После запуска приложение доступно по адресу:

```text
http://localhost:3000
```
